# Codex Remote

## 推荐：官方 CLI 终端模式

当前供应商拒绝 app-server 请求时，使用网页直连真正的官方 Codex CLI。终端画面由 xterm.js 渲染，输入通过 node-pty 传入官方 `codex` 进程，不修改客户端标识或全局供应商配置。

```powershell
cd E:\Code_Tool\RemoteControl
npm ci
npm start
```

默认打开 **http://127.0.0.1:8789**，配对码仍是 `.remote-token` 中的内容。点“创建一个会话”，输入项目路径，等待原生 CLI 输入提示出现后发送需求。首次打开项目时，如 CLI 显示项目信任菜单，使用方向键和 Enter 选择。

### 手机与电脑共享终端

电脑也通过本网页创建会话，手机点击“连接正在运行的终端”，或在侧栏选择同一个终端，即可不中断地继续输入。多个终端时需自行选择；这不会恢复历史或启动另一个 CLI。

输入草稿按终端保存在当前浏览器，刷新和切换会话后可恢复；断线期间可以继续编辑。发送成功仅表示文字已送入终端并按 Enter，请查看终端确认 CLI 响应。发送结果不确定时保留草稿，不自动重发。共享终端的各设备应协调输入，终端尺寸仍由最后调整窗口的设备决定。

检测到原生会话占用提示时，网页显示重试按钮并禁用发送；退出电脑端该会话后点击按钮即可发送小写 `r`。该提示基于当前终端画面识别，审批、信任菜单和其他 CLI 状态仍以原生终端为准。

### 终端版的历史任务

左侧“Codex 历史任务”会列出本机保存的会话，支持搜索、加载更多、只读预览和加载更早对话。点击“在终端中继续”才会运行官方 `codex resume`；不会在预览时占用原会话，也不通过 app-server 发起模型推理。原客户端仍在占用同一会话时，请先退出原会话再恢复。

如果手机终端提示 **“This conversation is open in another app”**，说明同一段对话仍被其他客户端占用。继续同一段对话的方法：

1. 先退出电脑端这段会话。
2. 在手机点击“终端键盘”，输入小写 `r` 重试。
3. 等待 CLI 输入框恢复后再发送消息；占用提示期间输入的消息可能没有提交，需要重新发送。

如果旧的 8789 服务已经在运行，且有需要保留的任务，在新终端中执行：

```powershell
cd E:\Code_Tool\RemoteControl
npm run start:history
```

打开 **http://127.0.0.1:8790**。这个入口复用原 8789 服务的终端、登录及输入，不会停止或复制正在运行的 CLI；配对码相同，原服务需要继续运行。历史读取在新服务中进行，不发起模型请求。关闭新版页面服务也不会关闭原服务中的任务。

手机如果通过 Tailscale Serve 访问，需要将其目标改为 `http://127.0.0.1:8790` 才能进入新版历史页面。日后没有任务运行时，可按正常方式重启 `npm start`，直接在 8789 使用新功能，不再需要这个升级入口。

- **文字输入**：下方大输入框支持中文和多行；“发送”会粘贴文字并按 Enter。只在 CLI 输入框就绪时使用，审批菜单请使用快捷键。
- **审批与问答**：使用 ↑ ↓ 选择，Enter 确认，Esc 返回；Ctrl+C 中断当前操作。请阅读原生菜单内容后选择。
- **直接操作终端**：点“终端键盘”可在终端内打字，支持原生 CLI 快捷键。Ctrl+C 有选中文本时用于复制，无选中时传给 CLI。
- **断线恢复**：关闭网页、刷新或网络断开不会结束 CLI；重新连接会恢复终端画面及最近 3000 行。会话保存在服务内存中，重启服务需要用已保存的 Codex 会话 ID 恢复。
- **终端尺寸**：同时连接同一会话时共享尺寸，最后一次调整浏览器窗口的设备决定尺寸。
- **关闭会话**：需要二次确认，会结束 CLI 和正在进行的任务。只是离开时直接关闭网页即可。
- **恢复历史**：创建终端时可填写 Codex 历史会话 ID，调用官方 `codex resume`。原会话被占用时，CLI 会显示原因；不能直接接管既有 PowerShell 窗口。

CLI 使用 `--no-daemon --no-alt-screen --ask-for-approval on-request --sandbox workspace-write`，审批交由用户，不绕过审批。使用本机原有登录与模型设置，无需额外输入 API key。供应商是否接受以实际推理为准；本环境已通过一条不读写文件的真实请求验证。

手机在同一 Wi-Fi：运行 `.\start.ps1 -ListenAddress 0.0.0.0`，访问 `http://电脑局域网IP:8789`。外网仍推荐电脑、手机登录同一 Tailscale 网络，再运行：

```powershell
tailscale serve --bg http://127.0.0.1:8789
```

使用 Tailscale 给出的 HTTPS 地址配对。电脑需保持开机、不休眠，Node 服务需要持续运行。这个端口需要手机实际连入局域网或 Tailscale，不能直接通过手机的 `127.0.0.1` 访问电脑。

首次安装在 Windows 使用 node-pty 的预编译组件；Linux 安装可能需要 C++ 编译环境。如果新版 npm 提示阻止 node-pty 安装脚本，并且启动提示缺少本机组件，可审阅后运行 `npm install-scripts approve node-pty` 并重新安装。

验证命令：`npm test`、`npm run check:terminal`。`npm run check:provider` 会启动真实 CLI，发起一条模型请求，并在结束后关闭验证终端。

### 旧版结构化模式

以下说明保留给支持 app-server 的供应商。通过 `npm run start:structured` 启动，默认端口为 8787；旧的演示命令 `npm run demo` 仍然可用。供应商如果返回 “This account only allows Codex official clients”，请使用上方的官方 CLI 终端模式。

给本机 Codex 加一个手机和电脑都能使用的网页工作台：实时进度、对话、命令输出、代码 diff、补充需求、停止任务，以及逐条审批。

基于官方 **Codex app-server** JSONL 协议，不解析终端截图，不需要 tmux。可以直接运行在 Windows，也可以在 WSL/Linux 中运行。网页使用哪一个 Codex 账户、配置和开发环境，取决于服务启动时的用户与系统环境。

## 启动

需要 Node.js 22+，以及已安装并登录的 Codex CLI。本项目在 Windows / Codex 0.162.1 验证。

```powershell
cd E:\Code_Tool\RemoteControl
npm run start:structured
```

打开 **http://127.0.0.1:8787**。首次运行自动生成 `.remote-token`；在本机查看，把内容输入网页配对框：

```powershell
Get-Content .remote-token
```

点“开始一个任务”，填写项目的绝对路径，然后发送需求。模型使用现有 Codex 配置，本项目不要求另外填写 API key。审批模式为 `untrusted`，工作区沙箱为 `workspace-write`，审批由用户处理；不会修改你的全局配置。只有 Codex 实际发起审批时，网页才显示审批卡片。

运行中的网页任务可继续发送补充消息；需要终止时点击“停止”。点击其他历史任务会先只读查看，不占用原会话，显示最近 30 轮，并每 8 秒刷新已保存的历史；这不是原客户端的实时输出镜像。当前不提供更早历史的翻页界面。

需要继续时点击“接管并继续”。如果原客户端仍然持有会话，网页保留只读历史并显示“重试接管”和“复制为新会话”。退出原客户端的该会话后可以重试；或者复制对话历史，在新会话中继续。**副本仍使用原项目文件夹，不会自动创建 Git worktree 或隔离文件**，避免在两个会话中同时修改相同文件。

**重要边界：本工具管理它自己的 app-server 任务，不接管其他 PowerShell / tmux 窗口中的实时终端。** 被占用任务仍可只读查看；执行审批、停止和补充指令仅适用于网页已接管或创建的会话。

## 手机访问

### 同一个 Wi-Fi

```powershell
.\start.ps1 -ListenAddress 0.0.0.0
```

通过 `ipconfig` 查看电脑的局域网 IPv4 地址，在手机浏览器打开 `http://电脑IP:8787`，输入相同配对码。Windows 如提示防火墙访问权限，允许所使用的专用网络即可。

### 外网访问：推荐 Tailscale

电脑和手机安装 Tailscale 并登录同一个网络。保持本服务默认监听 `127.0.0.1:8787`，在电脑上另开终端执行：

```powershell
tailscale serve --bg http://127.0.0.1:8787
```

手机使用 Tailscale 显示的 HTTPS 地址，再输入网页配对码。这里使用私有网络的 Serve，不需要 Funnel，也不需要把终端端口公开到互联网。Tailscale 需要自行安装、登录；本项目不会代替你完成账户配对或修改路由器。

如果已经有 HTTPS 反向代理，保持 Host/Origin 一致，并关闭 `/api/events` 的响应缓冲。可设置 `COOKIE_SECURE=1`，让配对 Cookie 只通过 HTTPS 发送。

## 离线与后台

- 关闭手机页面或网络断开，不会停止服务端任务；再次连接会同步状态和待审批请求。
- **服务进程必须持续运行，电脑不能睡眠。** 停止 Node 服务也会关闭它启动的 Codex 后端；重启后可恢复保存的历史，但不会自动继续中断的任务或保留旧审批。
- 网页配对 24 小时有效，服务重启后需要重新配对。配对码保存在本机，不会传给模型。
- 默认仅在本机开放。远程连接建议用 Tailscale HTTPS；配对码拥有操作该服务端 Codex 的权限。

## 支持的请求

- 命令执行 / 文件修改：批准本次或拒绝，不提供永久放行。
- 权限请求：允许请求的权限，仅限当前轮，或拒绝。
- 用户提问：选项或自由输入，支持多个问题。
- MCP elicitation：当前只支持拒绝；其他特殊请求显示原始信息，可停止任务。
- 命令实时输出、任务计划、最终回复、文件改动和聚合 diff。

不提供手机推送、独立 App、任意终端键盘接管或命令标准输入面板。网页适配手机浏览器，可以添加到主屏幕作为入口；没有离线 PWA 功能。

## 演示与验证

```powershell
npm run demo
```

演示不调用模型，不修改项目文件。发一条消息即可体验审批和结果。演示与真实模式请不要同时占用同一端口。

```powershell
npm ci
npm test
npm run check:ui
```

终端模式依赖 node-pty 与 xterm.js。开发依赖 Playwright 用于桌面 / 手机浏览器验证；`check:ui` 和 `check:terminal` 默认使用本机 Edge，在没有 Edge 的系统可修改脚本选择已安装的 Chromium。浏览器截图保存在 `test-results/`。

本机验证了真实 Codex 的初始化、创建任务和历史分页；完整消息 / 补充输入 / 审批 / 重连流程使用演示后端验证，没有为测试发起付费模型推理。

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 监听地址 |
| `PORT` | `8787` | 网页端口 |
| `REMOTE_TOKEN` | 自动生成并保存 | 自定义配对码，建议使用高熵随机值 |
| `CODEX_BIN` | 自动查找 | Codex 原生可执行文件路径；Windows 不要填写 `.cmd`/`.ps1` 包装脚本 |
| `COOKIE_SECURE` | 不启用 | HTTPS 代理部署可设置为 `1` |

协议参考：[OpenAI Docs — Codex App Server](https://developers.openai.com/codex/app-server/)。
